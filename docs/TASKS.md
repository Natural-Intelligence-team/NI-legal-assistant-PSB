# Задачи команды

Каждую задачу или связанный набор задач делаем в отдельной ветке. В `main` изменения попадают через pull request.

## Александр — документы и поиск

1. **Загрузить базу документов**

   - [ ] Прочитать архив базы, посчитать документы и проверить, что текст каждого файла доступен.
   - [ ] Разбить тексты по пунктам и абзацам. Сохранить заголовки, номера пунктов и текст для цитирования.
   - [ ] Задать постоянные ID документов и фрагментов. У каждой редакции документа свой ID.
   - [ ] Добавить получение полного документа по ID и проверить это на одном примере из базы.

2. **Сделать поиск по документам**

   - [ ] Подготовить слова и номера для поиска. Учесть регистр, `ё/е` и варианты написания номеров договоров.
   - [ ] Построить индекс BM25 и выдавать найденные фрагменты по [формату данных](DATA_FORMAT.md#результат-поиска).
   - [ ] Учитывать точный номер договора и название контрагента. Проверить различение «Альфа-Трейд» и «Альфа-Трейдинг».
   - [ ] Подключить поиск к обработчику Дианы. Проверить на одном вопросе, что найденный документ открывается по ID.

3. **Учесть даты и проверить выдачу**

   - [ ] Занести даты действия редакций и условия применения допсоглашений из документов.
   - [ ] Связать договоры с допсоглашениями, а регламенты с дополняющими документами. Возвращать фрагменты, которые нужны вместе.
   - [ ] Выбирать редакцию на дату события. Возвращать отдельный статус, если нужна дата или в базе отсутствует нужная редакция.
   - [ ] Разметить нужные документы и пункты на демо-вопросах. Проверить поиск по переформулировкам, дате и нескольким связанным документам.
   - [ ] Исправить пропуски и неверный выбор редакций. Сохранить список известных пробелов для итоговой проверки ответов.

## Диана

1. **Создать сервер и подключить модель**

   - [ ] Создать проект FastAPI, зафиксировать версии зависимостей и проверить локальный запуск.
   - [ ] Добавить схемы запроса, ответа и ошибки по [формату данных](DATA_FORMAT.md).
   - [ ] Добавить `.env.example` и исключить рабочий `.env` из Git. Прочитать настройки по [параметрам платформы](REQUIREMENTS.md#подключение-модели).
   - [ ] Написать клиент модели с тайм-аутом. Проверить тестовый ответ и обработку недоступности API.

2. **Реализовать обработку вопросов**

   - [ ] Создать общий обработчик и проверить его на одном тестовом фрагменте.
   - [ ] Подключить поиск Александра по [описанию результата поиска](DATA_FORMAT.md#результат-поиска) и передать найденные фрагменты модели.
   - [ ] Проверять ID и цитаты по найденному тексту и возвращать ссылки на документы.
   - [ ] Добавить в API два маршрута для отправки вопроса и получения документа по ID.
   - [ ] Добавить обработку истории, уточнение даты, частичный ответ, отказ при нехватке данных и исправление неверной предпосылки.
   - [ ] Проверить, что модель опирается на найденные положения и игнорирует инструкции внутри документов. На демо-вопросах сверить смысл выводов, цитаты и выбор редакции.

3. **Подготовить сабмит**

   - [ ] Написать `solution.py`. Он читает вопросы и базу из `DATA_DIR`, вызывает общий обработчик и записывает UTF-8 CSV с колонками `id,answer` в рабочую папку.
   - [ ] Проверить вывод на демо-вопросах. Для каждого ID нужен один непустой ответ, включая вопросы с историей. Замерить время работы.
   - [ ] Запустить решение из ZIP, собранного Дмитрием, в отдельной папке. Проверить лимиты и состав архива. Отправить пробный сабмит и записать оценку.
   - [ ] Исправить ошибки по результатам прогона и перепроверить финальный архив. Зафиксировать балл платформы и версию исходников, из которой собран архив.

## Дмитрий

1. **Собрать экран чата**

   - [ ] Создать `frontend/` на React + TypeScript + Vite. Зафиксировать зависимости и проверить запуск.
   - [ ] Сделать поле ввода, отправку вопроса и вывод сообщений.
   - [ ] Перенести [типы и моки](DATA_FORMAT.md#моки-для-интерфейса) в `frontend/src/api/`. Показать ответ, ожидание, уточнение, ошибку и список источников.

2. **Подключить сервер и источники**

   - [ ] Подключить отправку вопроса к серверу и показать настоящий ответ.
   - [ ] Передавать историю сообщений и добавить кнопку нового диалога.
   - [ ] Сделать карточки источников. По нажатию открывать документ по ID и выделять цитату из ответа.
   - [ ] Пройти в браузере обычный вопрос, уточнение, отказ и сбой сервера. Проверить повтор запроса и новый диалог.

3. **Подготовить запуск и демонстрацию**

   - [ ] Когда готов `solution.py`, собрать ZIP с нужными файлами в корне по [требованиям платформы](REQUIREMENTS.md#автоматическая-проверка). Передать архив Диане для прогона.
   - [ ] Добавить `Dockerfile`, `compose.yaml` и `.dockerignore`. Собрать интерфейс и запустить чат вместе с сервером.
   - [ ] Записать в README команду запуска, настройки, порт и шаги проверки. Проверить запуск с чистой копии проекта вместе с другим участником.
   - [ ] Подготовить PDF-презентацию и пройти демонстрацию. Показать ответ с источником, отказ и вопрос с датой.
   - [ ] Собрать финальный комплект по [списку сдачи](REQUIREMENTS.md#финальная-сдача) и проверить, что жюри сможет открыть материалы.
