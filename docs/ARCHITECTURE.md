# Архитектура и стек

Веб-чат и скрипт для платформы будут использовать общий поиск и общую подготовку ответа.

## Как проходит вопрос

Чат → сервер → поиск фрагментов → модель → проверка ответа → ответ с источниками.

Сервер учитывает историю диалога и дату события, из ответа пользователь может открыть документ и подтверждающий фрагмент. 
При нехватке данных ассистент объясняет это или задаёт уточнение.

## Стек

| Часть | Технологии | Для чего |
|---|---|---|
| Интерфейс | [React + TypeScript + Vite](https://react.dev/learn/build-a-react-app-from-scratch), CSS | Чат, состояния ожидания и ошибок, просмотр источников |
| Сервер | Python 3.12, [FastAPI](https://fastapi.tiangolo.com/), Uvicorn | Приём вопросов и соединение всех частей |
| Обмен данными | Pydantic, JSON | [Формат вопроса, ответа, фрагментов и цитат](DATA_FORMAT.md) |
| Поиск | BM25, библиотека [rank-bm25](https://github.com/dorianbrown/rank_bm25) | Поиск по словам, номерам документов и контрагентам |
| Генерация | DeepSeek V4.1 Flash через API организаторов; клиент httpx | Ответ по найденным положениям |
| Хранение | Файлы документов и поисковый индекс в памяти | Работа с небольшим корпусом кейса |
| Проверки | pytest | Автоматические проверки поиска, ответов и форматов |
| Запуск | Docker + Docker Compose | Запуск всего приложения одной командой |

pytest делаем чистым нейрослопом, если кто-либо, конечно, не желает делать его ручками.

Версии фиксируем при создании проекта: Python-зависимости — в `requirements.txt`, фронтенд — в `package-lock.json`. Для сабмита используем только разрешённые организаторами Python-библиотеки.

Если проверки покажут пробелы в поиске, добавим что-нибудь по типу BAAI/bge-m3 для поиска по смыслу и Qwen3 Reranker 8B для отбора фрагментов через тот же прокси организаторов, если получится. 
Векторы можно сравнивать через NumPy, cначала проверяем пользу на одинаковых вопросах.

## Правила реализации

- Каждый правовой вывод подтверждается документом; проверяем и цитату, и смысл вывода.
- Учитываем редакции и допсоглашения на дату события. При отсутствии старой редакции закона сообщаем об этом.
- Текст документов не может менять инструкции ассистента. Правовые основания берём только из базы кейса.
- Адрес, ключ и имя модели задаём через окружение. Ключ хранится на сервере, вне репозитория.
- Для финального приложения собираем интерфейс Vite и раздаём его через FastAPI.
- Для платформы собираем отдельный ZIP: `solution.py`, общие Python-модули и `requirements.txt` в корне.
