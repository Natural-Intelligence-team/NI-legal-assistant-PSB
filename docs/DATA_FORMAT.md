# Формат поиска и чата

## Моки для интерфейса

Дмитрий может собрать чат и просмотр документов на условных данных. После создания проекта Vite перенесите оба файла в `frontend/src/api/`. [Типы TypeScript](../examples/chat/types.ts) · [Готовые моки](../examples/chat/mocks.ts)

В обработчике отправки используйте `mockSendQuestion(request)`. Ответ приходит с небольшой задержкой, поэтому можно проверить экран ожидания. Вторым аргументом можно передать `partial`, `clarify`, `insufficient`, `refused` или `error` для проверки соответствующего сценария. `mockGetDocument(sourceId)` возвращает полный документ по ID из цитаты. При ошибке обе функции отклоняют запрос с `Error`, текст доступен в `message`.

```ts
import { mockChatRequest, mockGetDocument, mockSendQuestion } from "./mocks";

const response = await mockSendQuestion(mockChatRequest);
const citation = response.citations[0];
if (citation) {
  const document = await mockGetDocument(citation.source_id);
  console.log(document.title, citation.quote);
}
```

Когда сервер будет готов, клиент чата вызовет `POST /api/chat` и `GET /api/documents/{source_id}` с теми же типами. Пустой массив `citations` скрывает список источников. Состояние ожидания хранит интерфейс на время запроса.

## Результат поиска

Модуль Александра принимает `query` с текстом вопроса и `event_date` с датой события в формате `YYYY-MM-DD` или `null`. Он возвращает статус и список фрагментов в порядке релевантности. Диана использует `source_id`, чтобы получить полный документ, и `fragment_id`, чтобы проверить цитату.

```json
{
  "status": "ok",
  "fragments": [
    {
      "source_id": "contract-demo-v1",
      "fragment_id": "contract-demo-v1-4-2",
      "title": "Договор поставки № Д-01",
      "section": "4.2",
      "text": "4.2. Оплата производится в течение 30 календарных дней после подписания УПД."
    }
  ]
}
```

Данные в примере условные.

| Поле | Значение |
|---|---|
| `source_id` | ID документа. У каждой редакции свой ID. |
| `fragment_id` | ID фрагмента. При повторной загрузке той же базы ID сохраняется. |
| `title` | Название документа для отображения в чате. |
| `section` | Номер пункта строкой. Если номера нет, передаём `null`. |
| `text` | Текст фрагмента из документа. |

`ok` означает, что найдены фрагменты. Если подходящих фрагментов нет, возвращаем `not_found` и `fragments: []`. Если для выбора редакции нужна дата, возвращаем `date_required`. Если редакции на нужную дату нет в базе, возвращаем `edition_unavailable`. В обоих случаях передаём пустой список, чтобы сервер мог запросить дату или объяснить, чего не хватает.

## Запрос и ответ чата

Дмитрий отправляет вопрос и предыдущие сообщения через `POST /api/chat`. В новом диалоге история пустая. Текущий вопрос передаётся только в `question`.

```json
{
  "question": "Какой срок оплаты по договору Д-01?",
  "history": []
}
```

Элемент `history` содержит `role` (`user` или `assistant`) и `content` с текстом сообщения. Сервер Дианы возвращает ответ и подтверждающие цитаты.

```json
{
  "status": "answered",
  "answer": "Оплату нужно произвести в течение 30 календарных дней после подписания УПД.",
  "citations": [
    {
      "source_id": "contract-demo-v1",
      "fragment_id": "contract-demo-v1-4-2",
      "title": "Договор поставки № Д-01",
      "section": "4.2",
      "quote": "Оплата производится в течение 30 календарных дней после подписания УПД."
    }
  ]
}
```

`status` может быть `answered` (ответ), `partial` (частичный ответ), `clarify` (уточнение), `insufficient` (в базе мало сведений) или `refused` (отказ). Исправление неверной предпосылки с подтверждением возвращается как `answered`. `answer` содержит текст для чата. При отсутствии цитат передаём `citations: []`.

Техническая ошибка приходит с HTTP-кодом ошибки и JSON, например `{"error": "Модель недоступна"}`. Для отсутствующего документа используется `404`, для недоступной модели — `503`. Интерфейс показывает `error` и даёт повторить запрос.

## Просмотр документа

По нажатию на источник Дмитрий вызывает `GET /api/documents/{source_id}`. Сервер возвращает `source_id`, `title` и полный `text` документа. Интерфейс показывает документ и выделяет `quote` из ответа. Цитата должна дословно встречаться в исходном фрагменте.
